## What this is

**AiimanFolio.Pro** — a premium dark-navy + gold portfolio/blog site for a senior product engineer. Built with TanStack Start (SSR), deployed to Vercel (Node.js serverless) via `api/index.ts` adapter + `vercel.json`. Supabase handles the database (blog posts, contact messages).

## Commands

```bash
bun run dev        # dev server (Vite)
bun run build      # production build (Node.js/Vercel target)
bun run preview    # preview production build locally
bun run lint       # ESLint
bun run format     # Prettier
```

No test runner is configured.

## Architecture

### Stack
- **TanStack Start** (SSR framework on top of TanStack Router + Vite)
- **TanStack Router** — file-based routing under `src/routes/`; `routeTree.gen.ts` is auto-generated, never edit manually
- **TanStack Query** — data fetching; `QueryClient` lives in router context (`src/router.tsx`)
- **Tailwind CSS v4** — configured via `@theme inline` tokens in `src/styles.css` (not `tailwind.config.js`)
- **shadcn/ui** — "new-york" style, components at `src/components/ui/`
- **Supabase** — client at `src/integrations/supabase/client.ts`; types at `src/integrations/supabase/types.ts` (auto-generated)
- **Vercel** — `vercel.json` routing + `api/index.ts` as the serverless function entry; `src/server.ts` is the TanStack Start fetch handler (web fetch API, platform-agnostic)

### Vite config constraint
`vite.config.ts` uses `@lovable.dev/vite-tanstack-config` which already bundles: TanStack Start, React, Tailwind, tsconfig paths, Cloudflare plugin **disabled** via `cloudflare: false`. **Do not add these plugins again** — duplicates break the build.

### SSR entry points
- `src/server.ts` — web fetch API handler; wraps TanStack Start's server entry, normalizes h3 SSR errors, and adds cache headers
- `src/start.ts` — TanStack Start instance with a global error-catching middleware
- Both import `src/lib/error-capture.ts` to intercept unhandled SSR exceptions

### Routing
Routes live in `src/routes/`:
- `/` — full single-page portfolio (all sections composed in `index.tsx`)
- `/blog` — paginated blog index, queries Supabase client-side
- `/blog/$slug` — blog post detail, loaded via TanStack Router `loader` (SSR-compatible)
- `/projects` — projects grid with filtering
- `/contact` — contact form
- `/sitemap[.]xml` — dynamic sitemap route

Each route exports a `head()` function for per-page SEO meta/OG tags. The root route (`__root.tsx`) sets global defaults.

### Data layer
- `supabase` client (browser): import from `@/integrations/supabase/client`
- `supabase` server (SSR/middleware): import from `@/integrations/supabase/client.server.ts`
- `requireSupabaseAuth` middleware: `src/integrations/supabase/auth-middleware.ts` — use for protected server functions
- DB tables: `blog_posts` (with `status` enum: `draft`/`published`), `contact_messages`
- `src/integrations/supabase/types.ts` is auto-generated by Supabase CLI — never edit directly

### Design system
All design tokens are CSS custom properties in `src/styles.css` under `@theme inline`. The palette is fixed: dark navy (`#090B1F`) background, gold (`#F5B83B`) primary. **Never hardcode colors** — always use tokens.

Custom utility classes defined in `src/styles.css` `@layer components`:
- `.container-cf` — max-width centered container (use instead of Tailwind `container`)
- `.card-cf` — standard card with hover lift
- `.btn-gold` — primary CTA button
- `.btn-ghost` — outlined/ghost button
- `.chip` — label/badge pill
- `.gradient-text` — gold gradient text effect
- `.section-pad` — responsive vertical section padding
- `.prose-cf` — blog/article prose styling
- `.fade-up` — entrance animation

Fonts: **Space Grotesk** (`font-display`) for headings, **Inter** (`font-sans`) for body — loaded from Google Fonts in root `head()`.

### Component structure
- `src/components/site/` — page-level sections (Hero, About, Skills, Services, Stats, ExperienceTimeline, ProjectsGrid, Testimonials, LatestBlogs, Contact, Navbar, Footer)
- `src/components/ui/` — shadcn/ui primitives (don't modify, regenerate via `npx shadcn@latest add <component>`)

### Environment variables
Required at runtime (both client via `VITE_` prefix and server via `process.env`):
- `VITE_SUPABASE_URL` / `SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY` / `SUPABASE_PUBLISHABLE_KEY`

### Bun package management
`bunfig.toml` enforces a 24-hour supply-chain guard (`minimumReleaseAge = 86400`). To bypass for a specific package, add it to `minimumReleaseAgeExcludes` — confirm with the user first.
